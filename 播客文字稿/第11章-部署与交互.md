## 第一部分：合约部署原理

首先，我们来了解合约部署的原理。

在TON区块链上，合约部署是一个创建新账户的过程。每个智能合约都对应一个账户，账户有一个唯一的地址，合约的代码和数据都存储在这个账户里。

部署合约时，需要发送一个特殊的消息，叫做部署消息。这个消息包含两部分内容：

第一部分是合约的初始代码，也就是编译生成的字节码。这部分代码定义了合约的逻辑，一旦部署就不能修改。

第二部分是合约的初始数据，也就是合约的初始状态。这部分数据在部署时设置，之后可以通过合约函数修改。

TON使用一种特殊的地址格式。合约地址由两部分组成：工作链ID和账户ID。工作链ID表示合约运行在哪个工作链上，主网通常是0。账户ID是根据合约代码和数据计算出来的哈希值。

这意味着，同一个合约代码和初始数据，部署出来的地址总是相同的。这个特性很有用，比如你可以提前知道合约地址，甚至在部署前就可以往这个地址转账。

部署合约需要支付一定的费用，包括存储费和执行费。存储费是为了在区块链上保存合约代码和数据，执行费是为了执行部署时的初始化代码。

部署过程大致是这样的：

首先，你构建部署消息，包含合约代码和初始数据。

然后，你用钱包签名并发送这个消息到网络。

网络验证消息后，创建一个新的账户，存储合约代码和数据。

合约的初始化代码执行，设置初始状态。

部署完成，合约开始接收和处理消息。

在BluePrint框架中，部署过程被封装得很好。你只需要调用一个函数，框架会自动处理所有细节。

## 第二部分：部署脚本编写

了解了原理，我们来看看怎么写部署脚本。

部署脚本通常放在项目的scripts目录下。BluePrint创建项目时会自动生成一个部署脚本的模板，你可以基于这个模板修改。

一个典型的部署脚本是这样的结构：

首先，导入必要的模块。你需要导入合约的包装器、网络配置、钱包等。

```typescript
import { MyContract } from '../wrappers/MyContract';
import { NetworkProvider } from '@ton-community/blueprint';
```

然后，定义部署函数。这个函数接收一个NetworkProvider参数，它封装了网络连接的功能。

```typescript
export async function run(provider: NetworkProvider) {
  // 部署逻辑
}
```

在函数内部，首先创建合约实例。你可以设置合约的初始参数。

```typescript
const myContract = provider.open(
  await MyContract.fromInit(param1, param2)
);
```

fromInit函数会根据初始参数计算合约地址，并准备部署消息。

接下来，发送部署交易。

```typescript
await myContract.sendDeploy(provider.sender(), {
  value: toNano('0.05'),  ;; 部署费用
});
```

这里我们指定了部署费用，0.05个TON通常足够了。费用会从这个交易的sender地址扣除。

最后，等待部署完成并验证。

```typescript
await provider.waitForDeploy(myContract.address);
console.log('Contract deployed at:', myContract.address);
```

waitForDeploy会等待合约部署完成，然后打印合约地址。

如果合约有初始化参数，你可以在fromInit中传入。这些参数会影响合约的初始状态，也会影响合约地址。

部署脚本还可以包含更多的逻辑。比如，部署后调用一些初始化函数，设置合约的初始配置。或者部署多个相互依赖的合约。

```typescript
// 部署代币合约
const token = provider.open(await Token.fromInit());
await token.sendDeploy(provider.sender(), { value: toNano('0.05') });
await provider.waitForDeploy(token.address);

// 部署支付合约，传入代币合约地址
const payment = provider.open(await Payment.fromInit(token.address));
await payment.sendDeploy(provider.sender(), { value: toNano('0.05') });
await provider.waitForDeploy(payment.address);

console.log('Token:', token.address);
console.log('Payment:', payment.address);
```

这个例子展示了如何部署两个相互依赖的合约。

## 第三部分：网络部署

脚本写好了，我们来看看如何在不同的网络上部署。

BluePrint支持多种网络环境。默认支持的有本地网络、测试网和主网。

本地网络是在你的电脑上运行的模拟区块链，主要用于开发和调试。本地网络的速度最快，不消耗真实的TON，但状态不会持久保存。

测试网是真实的区块链网络，但上面的代币没有价值。测试网用于在真实环境中测试合约，确保一切正常后再部署到主网。

主网是正式的生产环境，上面的操作会消耗真实的TON，合约会被真实用户使用。

部署时，你需要指定目标网络。BluePrint使用命令行参数来指定网络。

```bash
npx blueprint run deploy
```

这个命令会提示你选择网络。你可以选择local、testnet或mainnet。

你也可以直接在命令中指定网络：

```bash
npx blueprint run deploy --testnet
npx blueprint run deploy --mainnet
```

部署到测试网时，你需要有测试网的钱包和测试币。如果你按照第九章的内容配置了测试网环境，应该已经有了。

部署到主网时，你需要有主网的钱包和真实的TON代币。确保钱包里有足够的余额支付部署费用。

部署过程中，BluePrint会显示进度信息。你可以看到交易哈希、区块高度等信息。这些信息可以用来在区块链浏览器上查看交易详情。

如果部署失败，BluePrint会显示错误信息。常见的失败原因有：

余额不足：钱包里的TON不够支付部署费用。

网络问题：连接不到网络节点，检查网络配置。

代码错误：合约代码有bug，导致部署时执行失败。

参数错误：初始参数不合法，检查fromInit的参数。

部署成功后，一定要记录下合约地址。这个地址是用户与合约交互的入口，也是你在浏览器上查看合约状态的标识。

## 第四部分：合约交互

合约部署好了，接下来我们要学习如何与合约交互。

与合约交互主要有两种方式：读取状态和发送消息。

读取状态是免费的，不需要支付Gas费。你可以获取合约的当前状态、存储的数据、余额等信息。

发送消息会改变合约状态，需要支付Gas费。消息会被合约处理，可能触发状态变更、发送其他消息等。

在BluePrint中，读取状态很简单。合约包装器会自动生成getter方法的封装。

```typescript
// 读取计数器值
const counter = await myContract.getCounter();
console.log('Counter:', counter);

// 读取余额
const balance = await myContract.getBalance();
console.log('Balance:', balance);
```

发送消息稍微复杂一些。你需要构建消息，签名后发送到网络。

```typescript
// 发送增加计数器的消息
await myContract.sendIncrement(provider.sender(), {
  value: toNano('0.01'),  ;; 消息费用
});
```

这里我们调用了sendIncrement方法，它会构建并发送增加计数器的消息。value参数指定了随消息发送的TON数量，用于支付Gas费。

如果消息需要携带数据，可以在参数中传入。

```typescript
await myContract.sendTransfer(provider.sender(), {
  value: toNano('0.05'),
  to: destinationAddress,
  amount: 100n,
});
```

这个例子发送了一个转账消息，指定了目标地址和转账金额。

发送消息后，你可能需要等待交易确认。

```typescript
const result = await myContract.sendIncrement(provider.sender(), {
  value: toNano('0.01'),
});

// 等待交易确认
await result.wait();

// 验证状态变化
const newCounter = await myContract.getCounter();
console.log('New counter:', newCounter);
```

在实际应用中，合约交互通常集成在前端界面中。用户通过网页或App与合约交互，而不需要直接操作命令行。

## 第五部分：TON Connect集成

说到前端交互，就不得不提TON Connect。

TON Connect是TON生态的标准连接协议，它让用户可以安全地用钱包与DApp交互。用户不需要把私钥给DApp，只需要用钱包签名交易即可。

集成TON Connect，你的DApp就可以连接TON Keeper、Tonhub等各种钱包。

集成TON Connect需要几个步骤：

首先，安装TON Connect SDK。

```bash
npm install @tonconnect/sdk
```

然后，在你的前端应用中初始化TON Connect。

```typescript
import { TonConnect } from '@tonconnect/sdk';

const tonConnect = new TonConnect({
  manifestUrl: 'https://your-app.com/tonconnect-manifest.json'
});
```

manifest文件包含你的应用信息，比如名称、图标、描述等。钱包会显示这些信息给用户。

接下来，实现连接钱包的功能。

```typescript
// 检查是否已连接
if (tonConnect.connected) {
  console.log('Already connected:', tonConnect.account);
}

// 连接钱包
async function connectWallet() {
  const wallets = await tonConnect.getWallets();
  // 显示钱包列表供用户选择
  // 用户选择后调用 tonConnect.connect(wallet)
}
```

连接成功后，你可以获取用户的钱包地址，与合约交互。

```typescript
// 发送交易
async function sendTransaction() {
  const transaction = {
    validUntil: Math.floor(Date.now() / 1000) + 600,  ;; 10分钟后过期
    messages: [
      {
        address: contractAddress,
        amount: '10000000',  ;; 0.01 TON
        payload: incrementPayload,  ;; 消息体
      }
    ]
  };
  
  const result = await tonConnect.sendTransaction(transaction);
  console.log('Transaction sent:', result);
}
```

TON Connect会弹出钱包界面，让用户确认交易。用户确认后，钱包会签名并发送交易到网络。

TON Connect还提供了断开连接、监听连接状态变化等功能。完整的集成文档可以参考TON Connect的官方文档。

## 第六部分：生产环境注意事项

最后，我们来聊聊生产环境的注意事项。

部署到主网之前，一定要做好充分的准备。生产环境的任何失误都可能导致资金损失。

第一，充分测试。在测试网上进行全面的测试，包括功能测试、压力测试、安全测试。确保合约在各种情况下都能正常工作。

第二，代码审计。如果合约涉及大量资金，建议请专业的安全团队进行代码审计。他们可以发现你忽略的安全隐患。

第三，权限控制。合约中要有完善的权限管理机制。关键操作只能由特定角色执行，防止恶意调用。

第四，紧急机制。考虑实现暂停功能或升级机制。如果发现严重漏洞，可以暂停合约或升级到修复版本。

第五，监控告警。部署后要监控合约的活动，设置异常告警。如果发现异常交易，及时响应。

第六，文档完善。编写详细的合约文档，包括功能说明、接口定义、使用示例。方便其他开发者集成你的合约。

第七，Gas优化。生产环境的Gas消耗直接影响用户体验。优化合约代码，降低用户的交易成本。

第八，备份私钥。保管好部署合约的钱包私钥，建议用硬件钱包或多签钱包。私钥丢失或泄露可能导致无法控制的后果。

第九，社区沟通。如果是公开项目，建立社区沟通渠道。及时回应用户问题，处理bug报告。

第十，持续维护。合约部署不是终点，而是起点。持续监控、维护、优化，确保合约长期稳定运行。
