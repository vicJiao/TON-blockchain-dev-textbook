## 第一部分：合约编译流程

首先，我们来了解合约的编译流程。

智能合约是用高级语言编写的，但区块链只能执行低级字节码。编译就是把人类可读的高级代码转换成机器可执行的字节码的过程。

TON智能合约主要用FunC语言编写。FunC代码需要经过几个步骤才能变成可以在区块链上运行的代码。

第一步是预处理。编译器会处理代码中的宏定义、头文件引用等。这就像是写文章前的提纲整理，把各个部分组织好。

第二步是编译成Fift代码。Fift是TON的汇编语言，更接近机器语言。FunC编译器会把FunC代码翻译成Fift代码。

第三步是汇编成字节码。Fift解释器会把Fift代码转换成二进制字节码，这就是最终部署到区块链上的代码。

第四步是生成代码单元。字节码会被打包成代码单元，包含合约的初始代码和初始数据。

在BluePrint框架中，这些步骤都被封装好了。你只需要运行npm run build命令，框架就会自动完成整个编译流程。

编译完成后，你会在build目录下看到生成的文件。主要有这么几个：

首先是.fif文件，这是Fift汇编代码，人类可读，可以用来调试。

然后是.cell文件，这是二进制的代码单元，包含合约的字节码。

还有.ts文件，这是TypeScript的包装器代码，方便在JavaScript中调用合约。

编译过程中可能会遇到错误。常见的错误有语法错误、类型不匹配、未定义的变量等。编译器会给出错误信息和行号，根据提示修改代码即可。

这里有个小技巧：编译时加上--verbose参数，可以看到更详细的编译信息，有助于排查问题。

## 第二部分：测试框架介绍

编译通过了，接下来就是测试。测试是智能合约开发中最重要的环节之一。

为什么测试这么重要？因为智能合约一旦部署就无法修改，如果代码有漏洞，可能造成资金损失。而且区块链是公开透明的，漏洞很容易被黑客发现利用。

BluePrint框架内置了测试框架，基于Jest测试库。Jest是JavaScript生态最流行的测试框架之一，功能强大，使用简单。

测试框架提供了几个核心功能：

首先是本地区块链模拟。测试时不需要连接真实的区块链，框架会在本地模拟一个区块链环境。这样测试速度快，而且不消耗真实的Gas。

其次是合约部署模拟。你可以在测试中模拟部署合约，给合约设置初始状态。

还有交易模拟。你可以模拟发送消息给合约，验证合约的响应是否正确。

最后是状态验证。你可以检查合约的状态变量、余额等，确保合约行为符合预期。

测试文件通常放在tests目录下，以.spec.ts或.test.ts结尾。BluePrint创建项目时会自动生成一个示例测试文件，你可以参考它的写法。

运行测试的命令是npm run test。框架会执行所有测试文件，并输出测试结果。

## 第三部分：编写单元测试

好，我们来具体看看怎么写单元测试。

单元测试是针对合约中最小可测试单元的测试。通常是测试单个函数或单个功能点。单元测试应该独立、快速、可重复。

写单元测试的第一步是准备测试环境。在测试文件开头，我们需要导入必要的模块，初始化区块链模拟器。

```typescript
import { Blockchain } from '@ton-community/sandbox';
import { MyContract } from '../wrappers/MyContract';

describe('MyContract', () => {
  let blockchain: Blockchain;
  let contract: MyContract;
  
  beforeEach(async () => {
    blockchain = await Blockchain.create();
    // 部署合约...
  });
});
```

beforeEach是每个测试用例执行前都会运行的代码，用来初始化干净的环境。

接下来是部署合约。在测试中，我们需要模拟合约的部署过程。

```typescript
const deployer = await blockchain.treasury('deployer');
contract = blockchain.openContract(await MyContract.fromInit());

const deployResult = await contract.sendDeploy(deployer.getSender());
expect(deployResult.transactions).toHaveTransaction({
  from: deployer.address,
  to: contract.address,
  success: true,
});
```

这里我们创建了一个treasury账户作为部署者，然后部署合约，并验证部署交易是否成功。

treasury是测试框架提供的一个特殊账户，里面有无限的测试币，可以用来支付Gas费。

现在我们可以写具体的测试用例了。每个测试用例用it或test函数定义。

```typescript
it('should increment counter', async () => {
  // 调用合约的increment函数
  const result = await contract.sendIncrement(deployer.getSender());
  
  // 验证交易成功
  expect(result.transactions).toHaveTransaction({
    success: true,
  });
  
  // 验证计数器值
  const counter = await contract.getCounter();
  expect(counter).toBe(1n);
});
```

这个测试用例调用了合约的increment函数，然后验证计数器的值是否增加了。

写单元测试时，要注意覆盖各种情况：

正常情况：输入合法的数据，验证输出是否正确。

边界情况：测试边界值，比如0、最大值、最小值等。

错误情况：测试非法输入，验证合约是否正确处理错误。

权限测试：测试只有特定角色才能执行的操作。

每个功能点都应该有对应的测试用例。测试覆盖率越高，合约的可靠性就越高。

## 第四部分：集成测试

单元测试验证了单个功能点，但合约在实际使用中，会和其他合约、外部系统交互。这时候就需要集成测试。

集成测试验证多个组件在一起工作时的行为。比如，测试代币合约和DEX合约的交互，测试NFT市场和NFT合约的交互。

在TON中，合约之间通过消息通信。集成测试需要模拟这种消息传递。

假设我们有一个代币合约和一个支付合约，支付合约接受代币支付。集成测试可以这样写：

```typescript
it('should process payment with tokens', async () => {
  // 先给买家铸造一些代币
  await tokenContract.sendMint(buyer.getSender(), 1000n);
  
  // 买家授权支付合约使用代币
  await tokenContract.sendApprove(buyer.getSender(), paymentContract.address, 100n);
  
  // 调用支付合约
  const result = await paymentContract.sendPay(buyer.getSender(), 100n);
  
  // 验证代币转移
  expect(result.transactions).toHaveTransaction({
    from: tokenContract.address,
    to: paymentContract.address,
    success: true,
  });
  
  // 验证买家余额减少
  const buyerBalance = await tokenContract.getBalance(buyer.address);
  expect(buyerBalance).toBe(900n);
});
```

这个测试模拟了完整的支付流程：铸造代币、授权、支付、验证结果。

集成测试要注意验证消息链。在TON中，一个操作可能触发一连串的消息传递。测试时要验证整个消息链是否正确执行。

框架提供了强大的交易追踪功能。你可以查看所有交易的详细信息，包括发送方、接收方、消息内容、Gas消耗等。

```typescript
console.log(result.transactions);
```

打印出来可以看到完整的交易列表，方便调试。

## 第五部分：Gas消耗分析

测试不仅要验证功能正确，还要关注Gas消耗。Gas是执行合约操作需要支付的费用，优化Gas消耗可以降低用户成本。

BluePrint测试框架可以方便地获取Gas消耗信息。

```typescript
const result = await contract.sendSomeOperation(sender.getSender());
const gasUsed = result.transactions[1].gasUsed;
console.log(`Gas used: ${gasUsed}`);
```

gasUsed显示了执行交易消耗的Gas数量。TON的Gas价格会波动，但一般来说，越少的Gas消耗意味着越低的交易成本。

如何优化Gas消耗呢？

第一，减少存储操作。存储数据到区块链是最昂贵的操作之一。尽量只存储必要的数据，可以考虑把大数据放到链下存储。

第二，优化计算逻辑。复杂的计算会消耗更多Gas。简化逻辑，避免不必要的循环和递归。

第三，使用更紧凑的数据结构。比如，用整数代替字符串，用位运算代替数组操作。

第四，批量操作。如果需要处理多个项目，尽量在一个交易中批量处理，而不是发起多个交易。

第五，使用引用而不是复制。在Cell中存储数据时，使用引用可以避免重复存储相同的数据。

在测试阶段，建议为关键操作建立Gas基准。记录正常情况下消耗多少Gas，如果某次修改后Gas消耗大幅增加，就需要检查是否有问题。

## 第六部分：调试技巧

最后，我们来聊聊调试技巧。写合约难免会遇到bug，掌握调试技巧可以事半功倍。

第一个技巧是打印日志。FunC支持在合约中打印日志，虽然生产环境不建议保留太多日志，但调试时非常有用。

```func
;; 在FunC中打印日志
dump(x);  ;; 打印变量x的值
```

dump函数可以把变量的值输出到日志中，帮助你看清程序执行时的状态。

第二个技巧是使用测试框架的调试功能。BluePrint允许你单步执行交易，查看每一步的状态变化。

```typescript
const result = await contract.sendOperation(sender.getSender());
for (const tx of result.transactions) {
  console.log('Transaction:', tx);
  console.log('Gas used:', tx.gasUsed);
  console.log('VM logs:', tx.vmLogs);
}
```

vmLogs包含了虚拟机执行的详细日志，可以看到合约执行的每一步。

第三个技巧是查看Fift代码。编译生成的Fift代码是人类可读的汇编代码，可以帮助你理解合约的底层行为。

```bash
npm run build
cat build/MyContract.fif
```

阅读Fift代码需要一些学习成本，但对于深入理解TON虚拟机很有帮助。

第四个技巧是状态检查。在关键位置检查合约的状态变量，确保状态符合预期。

```typescript
// 操作前检查状态
const stateBefore = await contract.getState();

// 执行操作
await contract.sendOperation(sender.getSender());

// 操作后检查状态
const stateAfter = await contract.getState();
expect(stateAfter).not.toEqual(stateBefore);
```

第五个技巧是异常测试。故意触发错误情况，验证合约的错误处理是否正确。

```typescript
it('should reject invalid input', async () => {
  const result = await contract.sendInvalidOperation(sender.getSender());
  expect(result.transactions).toHaveTransaction({
    success: false,
    exitCode: 100,  ;; 预期的错误码
  });
});
```

好的错误处理可以让合约更安全，也更容易调试。
